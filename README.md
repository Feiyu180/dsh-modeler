# dsh-modeler · 三视图建模插件

用**前 / 侧 / 俯三张正交视图**雕出三维模型，在 DSH 网页里用 three.js 实时预览，
导出 OBJ / STL / GLB。核心算法零依赖，纯 JS（Node 与浏览器共用同一份）。

```
三张视图 PNG ──► 剪影(二值) ──► 体素雕刻(视觉壳) ──► Chamfer 距离场 ──► Surface Nets ──► 水密网格
                    │                  │                   │                │
                 阈值/填洞         三视图取交          内部负/外部正      对偶等值面
```

> **测试环境**：文中所有实测数据（耗时、显存、顶点数、体积等）均来自 **RTX 5060 Laptop（8 GB 显存）**。

---

## 1. 怎么用

### 1.1 在 DSH 里用（主路径）

1. 左侧栏底部、**「设置」上方**有一个 **`◧ 三视图建模`** 按钮 —— 点开。
2. 弹出的面板里有三张卡片：**前视图 / 侧视图 / 俯视图**。
   把图**拖进去**，或点一下选文件。也支持 `Ctrl+V` 直接粘贴截图
   （会自动填进第一个空槽）。
3. 拖完自动出模型：中间是 three.js 视口，可以拖动旋转、滚轮缩放。
4. 参数不够好就调（都是即时重算）：
   - **分辨率** —— 体素网格最长边，越大越细但越慢（24–192，默认 96）
   - **留白** —— 模型与包围盒的空隙比例
   - **平滑** —— 距离场模糊次数，消除体素台阶感（默认 1）
   - **去碎块** —— 删掉小于该体积的孤立连通块
   - **自动阈值** —— 用 Otsu 自动二值化；主体比背景亮时关掉并配合「反相」
   - **填空洞** —— 只填细小缝隙；**真实通孔会保留**（见 §4.2）
   - **侧视图镜像** —— 侧视图左右对不上时打开
   - **左右对称** —— 强制关于 X 对称（适合人脸/器皿这类对称物）
5. 满意了点 **「导出 ▾」** —— 展开一张导出卡（**所有模式通用**，不管网格是雕刻出来的还是 AI 出的）：

   | 卡里的项 | 说明 |
   |---|---|
   | **格式** | `gltf` / `glb` / `json` / `obj` / `stl`（二进制）/ `stl-ascii` |
   | **文件名** | 默认 `model`（host 落盘时重名会自动编号，**不覆盖**已有文件） |
   | **位置** | 填一个**绝对目录**就写进去；留空则每次弹系统保存对话框 |
   | 按钮 | `导出到该目录`（位置填了时）/ `另存为…`（强制弹系统对话框）/ `选择…`（DSH 原生目录选择器） |

   落盘有三条路，按这个优先级自动选（都在 `diag` 里留痕，出问题能查）：
   1. 位置框里填了目录 → `POST /export`，由 host 直接写盘（可反复导出、不弹窗）
   2. `showSaveFilePicker`（系统「另存为」对话框，自己挑文件夹和文件名）
   3. 浏览器下载（兜底，任何环境都能拿到文件）

   格式怎么选：**GLB** 体积最小、三维软件通吃；**glTF** 是文本、能直接看能 diff（缓冲内嵌
   成 data URI，单文件自包含，不是 gltf+bin 两件套）；**JSON** 是给程序和人看的留档 ——
   它把"这个网格怎么来的"（来源模式、雕刻参数、水密/体积/包围盒统计）和顶点、三角形放在
   同一个文件里，坐标按 1e-6 取整（精度远高于模型本身，19 万顶点约 10 MB），而且能被
   `modeler_load` 原样读回来（格式自证：`format: "dsh-modeler.mesh"`）；**STL** 给 3D 打印。
   六种格式都只含几何，没有材质/UV/法线。

### 1.2 让 Agent 帮你做（host 工具）

装了插件重启 DSH 后，会多出三个工具：

| 工具 | 干什么 |
|---|---|
| `modeler_save` | 把网格数据存成文件（OBJ / STL / STL-ASCII / GLB / **glTF** / **JSON**），默认写到会话工作区的 `Modeler/` |
| `modeler_load` | 读回一个模型文件（六种格式都能读，含本插件导出的 JSON 与 glTF），报顶点数/三角形数/**是否水密**/体积/包围盒 |
| `modeler_views` | 把模型**切片回三视图 PNG**（前/侧/俯 + 一张拼图），方便肉眼或视觉模型核对 |

`modeler_views` 的输出可以直接 `read_image` 看，所以"重建得像不像"是可以被验证的，不用猜。

> `modeler_save` / `modeler_load` 的 glTF、JSON 支持，以及导出到本地目录用的
> `POST /export`，都是 host 侧的改动 —— **要重启 DSH 才生效**；面板上的导出卡是客户端，
> 会自动热重载。面板在 host 还没重启时会自动回落到「另存为」并提示原因。

### 1.3 三视图的画法（决定成败）

| 视图 | 看向 | 宽 → | 高 → |
|---|---|---|---|
| 前视图 | 从物体正面（+Z）看 | 左右 **X** | 上下 **Y** |
| 侧视图 | 从物体右侧（−X）看 | 前后 **Z** | 上下 **Y** |
| 俯视图 | 从上往下（+Y）看 | 左右 **X** | 前后 **Z** |

- 三张图**各自的白边会被自动裁掉**，所以不用对齐画布，但**长宽比要真实**。
- 主体用**深色**画在**浅色**背景上（或反过来，配合「反相」）。
- 只给一两张也行：缺的那个轴按默认厚度 4 挤出去（相当于沿该轴拉伸该草图）。

### 2.1 AI 建模接入（可选）

面板里 AI 输入区是一个下拉 + 一个「环境与模型」按钮：

| 模式 | 模型 | 做什么 | 实测耗时 |
|---|---|---|---|
| `single` | TripoSR | 一张图直接出网格，最轻 | ~58 s |
| `zero123` | Stable Zero123 | 一张图绕圈出前/侧/俯三个视角 → 再走本插件的视觉外壳雕刻 | ~39 s |
| `hunyuan3d` | Hunyuan3D-2 | 三维原生生成（几何最细，无颜色；**不是水密网格，不能直接 3D 打印**） | ~130 s |
| `mv` | **Hunyuan3D-2mv** | **前/左/后(/右) 多视图一起推理** —— 背面不再靠猜（**需 ≥11 G 显存**，见下） | ~130 s |
| `views` | —— | 纯三视图融合（不调 AI） | —— |

> **多视图（`mv`）的边界，别记错**：它的四个视角是**绕物体一圈的方位角视角**
> （`front` / `left` / `back` / `right`，见 `MV_VIEWS`），**没有"俯视"槽** ——
> 工程三视图里的俯视图喂不进这个模型。顺序与命名有语义：host 侧按
> front→left→back→right 给每路加正弦位置编码再拼成一条条件序列
> （与 ComfyUI 的 `Hunyuan3Dv2ConditioningMultiView` 一致），给错不会报错、
> 只会生成一个视角错位的模型。
> 它和单图版的**模型结构完全相同**（实测两者 safetensors 张量表逐项一致：1649 个张量、
> 零形状差异），差别只在条件构造 + 微调权重；权重在 `AI-ModelScope/Hunyuan3D-2mv`，
> 一键安装清单里叫 `hunyuan3dmv`（4.59 GiB，复用单图版的 VAE 与 DINOv2 编码器）。

#### ⚠ 多视图需要多少显存（实测标定，不是估的）

条件序列长度 = **视角数 × 1370 token**，显存随视角数陡增。以下数据均在 **RTX 5060 Laptop（8 GB 显存）** 上实测：

换到 ≥11 G 的卡上即可直接用（≥16 G 放开到 4 个视角）。

## 3. 算法与关键约定

### 3.1 雕刻

每张视图取其**内容框**（去白边），三张图统一到同一个"每内容像素多少体素"的尺度
（`scale`，由最长边和分辨率决定），然后逐体素对三张掩码**取交**：

```
体素 (i,j,k) 被占据  ⟺  前视图(u=i)+ 侧视图(u=k)+ 俯视图(u=i,v=k) 三张都命中
```

得到的是**视觉壳（visual hull）** —— 对凸形状精确，对凹形状偏大（凹处会被填平）。
这是三视图重建的固有限制，不是实现问题。

### 3.2 距离场

- 用 **Chamfer 3-4-5** 两遍扫描近似欧氏距离，单位是 ×3。
- 约定：**内部为负、外部为正、表面在 0**。
- 外部距离以**实体**为种子；内部距离以**空格**为种子。

> ⚠ 这两个种子极易写反，而且写反之后**回归测试几乎全绿** —— 网格仍然水密、
> 体积和包围盒都对，只是距离场退化成二值 ±3、曲面细节变糙。
> 已修，并在 `tools/selftest.test.mjs` 里用"逐点看数值 + 线性梯度"守住。

### 3.3 Surface Nets（对偶等值面）

不用 Marching Cubes，也不用任何 256 项查找表：

- 每个"8 个角有正有负"的体素格 → **1 个顶点**（放在 12 条变号格边的交点加权平均处）
- 每条"两端异号"的格边 → **1 个四边形**（连该边周围 4 个格的顶点）
- 绕序由"内→外"方向自动判定（Newell 法线取与梯度同向的那个绕序）

拓扑由"每条变号格边恰好邻接 4 个变号格"这一几何事实保证，所以结果**必然闭合、必然流形**、
不会有 MC 那种歧义面。代价是平面处比 MC 略"胖"半格，用距离场平滑补偿。

## 4. 实现要点与已知陷阱（都在代码注释里留了记录）

### 4.1 距离场与网格的索引域必须一致
距离场的索引域若与占据体素错开一格，等值面采样就会错位 —— 表现为网格**破洞**。
现在数据流是：占据体素域 → 补 pad 层 → 距离场（同域）→ 平滑 → 转格点域 → Surface Nets，
每一步的维度都写清楚在 `meshFromVoxels` 的注释里。

### 4.2 填洞不能把设计上的孔填掉
剪影里的孔**往往就是设计意图**（方板中心孔、圆环、法兰螺栓孔）。一股脑填掉会让重建
变成一块实心板。现在的判据是按空洞连通域的**外接矩形最短边**：`< 5px` 视为描线缝隙（填），
否则保留。
（按面积占比判定也尝试过，但"细长缝隙"和"方形孔"的界限更模糊，故未采用。）

### 4.3 `pad=0` 时是"完全没有种子"的退化状态（**这条曾被写错，已按实测更正**）

> 第一版这里写的是"`pad=0` 时数组外当半空间背景参与计算，于是边界处内部距离被压到最小"。
> **这是错的。** 一轮独立审查（`review-chamfer.mjs` 的 D-1 节）用数值推翻了它：
> 9³ 全实心、`pad=0` 时，field 的取值集合只有一个元素 `-4194306 = -(BIG+3)` ——
> 也就是说**一个 0 种子都没有**，chamfer 全程走 `min(v, BIG+3) = BIG`，整个数组保持哨兵值。
> 那是"未定义"，不是"被压到最小"。

正确的语义：

| 情形 | 实际行为 |
|---|---|
| `pad=0`，块内没有任何空格 | 无种子 → 全场保持哨兵值（退化，无意义） |
| `pad=0`，块内/边界有空格 | 以那些空格为种子，正常工作 |
| `pad>=1` | 补出来的那层空格**就是**背景种子，表面被正确地"贴"到原始数组边界上 |

所以真实管线（`buildMesh` / `meshFromVoxels`）一律用 `pad>=1`，既避免退化，也保证等值面
不在数组边界被截断。测试里一律显式给 `pad`，就是为了躲开 `pad=0` 这个未定义角落。

### 4.3b 1 体素厚的结构**必然**重建出空网格（固有限制，不是 bug）

角点采样（体素域取 8 邻居平均 → 格点域）在厚度为 1 时，跨表面的格点恰好是
`(4×(-6) + 4×(+6)) / 8 = 0`，而 `surfaceNets` 用 `v < 0` 判内部 ⇒ **零个内部格点** ⇒ 无面可建。
厚度 ≥ 2 才有"完整的内部格点"。

实测（`review-thin.mjs`）：

| 厚度 | 格点扫描线上的负格点数 | 结果 |
|---|---|---|
| 1 | 0 | 0 顶点 0 三角形（**模型整体消失**） |
| 2 | 1 | 正常出网格 |
| 3 | 2 | 正常出网格 |

对策：`carve` 对每个轴有 `Math.max(2, …)` 保底，所以正常管线不会真的遇到 1 体素厚；
`buildMesh` 另有 `thicken`（默认开）对"某轴最长游程 ≤ 1"的方向补厚，并在
`meta.thickenedAxes` 里如实报告。若仍然为空，`meta.emptyReason` 会给出可操作提示
（"把分辨率调高"）。

### 4.3c 空网格不能被判为"水密"

0 个三角形时 `boundaryEdges` 也是 0，于是 `watertight` 会变成 `true` ——
`modeler_save` 曾因此写一个 0 字节几何的空文件，还附一句"网格水密，可以直接 3D 打印"。
现在 `meshStats` 对空网格返回 `empty: true, watertight: false`，host 在**落盘之前**拒绝，
客户端面板也会显示原因。

### 4.3d 局部薄特征：大模型里的悬空薄条曾被静默丢掉（已修）

这是独立审查里的 **[高]** 级问题，也是本项目最难找的一类 bug ——
因为它**完全不报错**：

```
三视图 = 主体 + 一条悬空的 1px 薄条
  薄条厚 1px ⇒ 网格 Y 范围 1..81    ← 薄条整条没了，只剩主体
  薄条厚 2px ⇒ 网格 Y 范围 1..121   ⇒ 薄条在
```

用户看到的是一个"正常的"模型，只是少了一个特征。根因同 §4.3b（跨表面格点平均成 0）。

**第一版修法打不到它**：按"整轴最长游程 ≤ 1"判，而悬空薄条所在的 Y 轴上主体有 80 层厚，
最长游程 = 80 ⇒ 不触发。

**第二版改用"域的最小包围盒跨度 ≤ 1"**：能修好轴对齐的薄条，
但对**斜置薄片**无效（包围盒跨度判不出来）。

**最终采用的是第三版方案**（`src/core/thicken.mjs` 的 `repairThinFeatures`），
判据是**精确的、不是启发式**：

> 实心体素 `v` 会被抹掉 ⟺ `v` 的 **3×3×3 格点邻域里一个负格点都没有**。
> （负格点 = 内部格点 = 等值面会经过的地方。周围没有负格点 ⇒ 表面到不了 `v` 附近
> ⇒ `v` 在输出网格里必然不存在。）

它断言这个判据与实际网格**逐位一致**（`surfaceCells == meshFromVoxels().vertexCount`）。
实测效果（采用之后）：

| 案例 | 结果 |
|---|---|
| 悬空薄条 1px | `path=repaired`，检出 14400 个，补 14400 体素（占整模 **0.83%**），`verified=true` |
| 悬空薄条 2px / 3px | 不触发（本来就能重建） |
| **斜置薄片**（第二版做不到） | 检出 80 个，`path=repaired`，`verified=true` |
| 8 个正常夹具 × 2 分辨率 | 全部零改动、零误伤 |

它的实现还有三点设计值得记下来：

- **廉价预筛**：肯定干净时直接跳过精确检测（省一次 `distanceField` + 格点域重采样）
- **零改动保证**：没检测到薄特征时**原样返回同一个数组引用**，一个体素都不动
- **验证闭环 + 不假装成功**：补完重跑检测，做不到就如实报 `verified: false` 与 `residual`

代价（该实现已注明）：修补方式是**局部双侧膨胀**，所以被救回来的薄特征会变厚
（1 体素 → 3 体素），位置精度降到 ±1 体素；好处是保住质心、不会被推偏。

两条硬约束都由回归守住：**悬空 1px 薄条能重建**、**正常夹具零误伤**
（正常模型 `thinRepair === null` 且 `thickenedAxes === []`）。

### 4.4 哨兵值不能参与加法溢出
未到达格点的哨兵曾用 `0x3fffffff`，`chamfer` 里做 `BIG + D1` 会溢出成负数，
表现为距离场冒出 `-1073741826` 这种值。现在用 `0x3fffff`（≈4.19e6），叠几十步也够不着 int32 上限。

### 4.4b Chamfer 3-4-5 的精度上限：−5.7% ~ +10.6%，且系统性高估

`review-chamfer.mjs` 用"单个空格种子、逐点比真实欧氏距离"测出来的：

| 方向 | chamfer/3 | 真实 | 误差 |
|---|---|---|---|
| (1,0,0) | 1.0000 | 1.0000 | **0.00%**（沿轴精确） |
| (1,1,0) | 1.3333 | 1.4142 | −5.72% |
| (2,1,1) | 2.6667 | 2.4495 | **+8.87%** |
| (3,2,1) | 4.0000 | 3.7417 | +6.90% |
| (2,2,1) | 3.0000 | 3.0000 | 0.00% |

整体：**平均绝对偏差 4.83%**，平均有符号偏差 +4.39%（高估）。
含义：**斜面上的等值面有同量级的亚体素位移** —— 这就是球/圆锥曲面看起来有台阶的原因之一。
要更准得换 `(1, √2, √3)` 权重或精确 EDT（Felzenszwalb）。
这是权重本身的固有误差，不是实现 bug。

### 4.4c `meshStats` 的边 key 不能用整数编码

曾用 `p * 2097152 + q` 图快（声称 p,q < 2²¹ 时精确）。后来构造出了**碰撞实例**：
两条完全不同的边共用同一个计数器 → 真值 6 条边界边只报 2 条 → 非流形网格被误判成水密。
触发条件是顶点数 ≥ 2²¹ = 2097152（当前管线达不到），但这是判"能不能 3D 打印"的公共函数，
已改回字符串 key。

### 4.5 Windows / PowerShell 5.1 写 `.ps1` 必须带 UTF-8 BOM
否则中文被按 ANSI(GBK) 解，直接**破坏语法**（报"字符串缺少终止符"）。
`install.ps1` 与 `tools/*.ps1` 都是带 BOM 的 UTF-8。

## 7. 已知限制

- **凹形状会偏大** —— 视觉壳的固有限制（凹处被填平）。需要精确凹造型请用多视角或手工建模。
- **没有文理/材质** —— 产出是纯几何，只有位置和索引。
- **曲面有台阶感** —— 两个原因叠加：① 距离场用 Chamfer 3-4-5，斜方向有 −5.7%~+10.6% 的
  量化误差（见 §4.4b）；② 顶点位置是"12 条变号格边交点加权平均"的一阶近似。
  平面为主的形状（方盒、L 形、方板）看不出来，球/圆锥/斜面上明显。
  缓解办法：把「平滑」调到 2~3、分辨率调高。
- **厚度 1 个体素的结构会整体消失**（见 §4.3b）。`carve` 有 `Math.max(2, …)` 保底，
  正常管线碰不到；若真遇到，`meta.emptyReason` 会提示提高分辨率。
- **STL 读回会"不水密"** —— 二进制 STL 的顶点不共享，读回来每条边只属于一个三角形。
  这是格式本身的性质；工具已按位置焊接后再判拓扑（`weldNote` 会说明），
  所以 `modeler_load` 对 STL 报的 `watertight` 是有意义的。用 OBJ/GLB 读回则本来就是水密的。
- **分辨率上限 320** —— 再高内存和耗时增长太快（320³ 距离场 ≈ 3×10⁷ 格 × 4 字节）。
